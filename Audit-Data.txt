4. JWT Auth Middleware and Protected Routes
JWT Implementation:

Located in middleware/auth.js
Uses jsonwebtoken library
Access token expiration: process.env.JWT_EXPIRE
Refresh token expiration: process.env.JWT_REFRESH_EXPIRE
Token verification in utils/generateToken.js
Authentication Middleware (authenticate):

Checks access token from:
Authorization header (Bearer token)
Cookies (accessToken or token)
Query parameter (accessToken)
Custom header (x-access-token)
Validates token format (3 parts separated by dots)
Verifies token signature and expiration
Attaches user to request object
Authorization Middleware (authorize):

Takes allowed roles as parameters
Checks user roles from database
Grants access if user has at least one allowed role
Roles: OWNER, INFLUENCER, ADMIN
Protected Routes:

All routes except signup, login, select-role, refresh-token, Google OAuth, password reset, onboarding endpoints require authentication
Role-specific routes use authorize() middleware:
Owner routes: authorize('OWNER')
Influencer routes: authorize('INFLUENCER')
Admin routes: authorize('ADMIN')
